# Glance Payload Contract

The reusable glance payload is generated by `buildGlancePayload(day)` and cached in local storage as `store.glancePayload`.

## Purpose

This object is the compact handoff for:

- WidgetKit timelines.
- Live Activity state.
- Apple Watch synced glance views.
- Future Android widgets or persistent notifications.

## Core Fields

- `version`: payload schema version.
- `generatedAt`: ISO timestamp when the web app generated the payload.
- `staleAt`: ISO timestamp after which the native surface should show stale state.
- `state`: `fresh`, `offline`, or `stale`.
- `spot`: active spot id, name, coordinates, and water mode.
- `species`: selected species id and label.
- `day`: selected forecast date and short label.
- `activity`: score, tone, and user-facing label.
- `window`: best window label, peak, reasons, and risks.
- `water`: tide or river compact state.
- `weather`: risk, wind, gust, precipitation, and marine values where available.
- `moon`: moon label and first major/minor solunar windows.
- `sourceAvailability`: source flags for weather, marine, tide, river, and solunar.

## Stale and Offline Behavior

- Weather-backed payloads are considered fresh for 90 minutes.
- Partial or cycle-only payloads are considered fresh for 30 minutes.
- Native surfaces should still render stale payloads, but with a visible `mis à jour` or stale indicator.
- Missing marine, tide, or river source flags should show `à confirmer` rather than empty fields.

## Size Rules

- Keep arrays capped to two reasons, two risks, and two water events.
- Do not include hourly arrays or full daily forecasts.
- Use labels already localized by the web layer for MVP native surfaces.
